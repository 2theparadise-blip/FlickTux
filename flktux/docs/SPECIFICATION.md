## 1. システム概要とアーキテクチャ設計

FlickTux は、ペンタブレット（Wacom Bamboo / Intuos 等）やトラックパッド、外付けテンキーを活用し、**「クリエイターがペンやペンタブから両手を離さずに文字入力できる環境」**および**「エクセル等の表計算でキーボードに一切触れず10キーだけで作業が完結する環境」**を提供する統合入力支援システムです。

## 2. 5大入力モード ＆ 10キー配列仕様

モード切替ボタン `[切替]` を押すことで、以下の5つのモードが順繰りに切り替わります：
`かな [あ]` ➔ `カタカナ [ア]` ➔ `英字 [A]` ➔ `数字 [1]` ➔ `ナビ/エクセル [↑]` ➔ `かな [あ]`

### 2.1 【新機能】エクセル・ナビゲーションモード (`↑`)

ユーザーの直感を最大限に活かし、**8・6・2・4 を十字カーソルキー、7・9 を Tab / Shift+Tab、1・3 を Shift / Ctrl** に割り当てた表計算・データ入力特化配列です。

```text
+-----------+-----------+-----------+-----------+
|   Esc     |   Home    |    End    |   ⌫ 消去  |  Row 0: 移動・取消・消去
+-----------+-----------+-----------+-----------+
|  Tab (7)  |  ▲ 上 (8) | S-Tab (9) |  PageUp   |  Row 1: 次列(Tab) / 上(▲) / 前列(S-Tab)
+-----------+-----------+-----------+-----------+
|  ◀ 左 (4) |  決定 (5) |  ▶ 右 (6) |  PageDown |  Row 2: 左(◀) / 決定(Ent) / 右(▶)
+-----------+-----------+-----------+-----------+
| Shift (1) |  ▼ 下 (2) |  Ctrl (3) |  +  次へ  |  Row 3: 範囲選択(Shift) / 下(▼) / 複写(Ctrl)
+-----------+-----------+-----------+-----------+
| Space (0) |  Del (.)  |  切替 [↑] |  Ent 確定 |  Row 4: 空白 / 削除 / モード切替 / 確定
+-----------+-----------+-----------+-----------+
```

#### エクセル / スプレッドシート作業シナリオ:
1. **連続数値入力 ➔ 右セル移動:**
   - 数字モード `[1]` で数値を打鍵 ➔ ナビモード `[↑]` に切り替えて `7 (Tab)` を押すだけで右のセルへ移動。
2. **前のセルへの修正戻り:**
   - `9 (S-Tab)` を押すと、即座に `Shift+Tab` が送られ、左のセルへ一瞬で戻る。
3. **行の確定 ➔ 次の行へ移動:**
   - `Ent (確定)` または `5 (決定)` を押すと、入力確定と同時に下の行の先頭セルへ改行移動。
4. **セルの範囲選択:**
   - `1 (Shift)` を押してラッチ（点灯）させた状態で `8 (▲)`, `6 (▶)`, `2 (▼)`, `4 (◀)` を押すと、セル範囲の矩形選択が可能。
5. **コピー＆ペースト:**
   - `3 (Ctrl)` と連携し、セル内容の複写・貼付も片手・ペン先で完了。

### 2.2 かなモード (`あ`)
```text
+-----------+-----------+-----------+-----------+
|   / 記号  |    ◀ 左   |    ▶ 右   |   ⌫ 消去  |  Row 0
+-----------+-----------+-----------+-----------+
|  7: あ行  |  8: か行  |  9: さ行  |   - 空白  |  Row 1
+-----------+-----------+-----------+-----------+
|  4: た行  |  5: な行  |  6: は行  |  変 変換  |  Row 2
+-----------+-----------+-----------+-----------+
|  1: ま行  |  2: や行  |  3: ら行  |  +  次へ  |  Row 3
+-----------+-----------+-----------+-----------+
|  0: わ行  |  .: 、。  |  切替[あ] |  Ent 確定 |  Row 4 (*は ゛゜小)
+-----------+-----------+-----------+-----------+
```
- **フリック:** 中央=あ段, 左=いだん, 上=う段, 右=え段, 下=お段
- **トグル連打:** 同一キー連打で `あ ➔ い ➔ う ➔ え ➔ お`（500ms無操作または `+ 次へ` で確定）。
- **濁点・小文字 (`*`):** 直前文字をアトミックに `か ➔ が ➔ か`、`は ➔ ば ➔ ぱ`、`つ ➔ っ` に置換。

```text
+-----------+-----------+-----------+-----------+
|   / 記号  |    ◀ 左   |    ▶ 右   |   ⌫ 消去  |  Row 0

+-----------+-----------+-----------+-----------+
```

- **英字フリック:**
  - `abc`: 中央=a, 左=b, 上=c, 右=2
  - `def`: 中央=d, 左=e, 上=f, 右=3
  - `ghi`: 中央=g, 左=h, 上=i, 右=4
  - `jkl`: 中央=j, 左=k, 上=l, 右=5
  - `mno`: 中央=m, 左=n, 上=o, 右=6

  - `@._/`: 中央=@, 左=., 上=_, 右=-, 下=/
  - `.,?!`: 中央=., 左=,, 上=?, 右=!, 下=-
- **大文字・小文字切替 (`a/A`):**
  - 直前の英字をアトミックに `a ➔ A ➔ a` とトグル変換。

## 3. 入力コア ＆ ハプティック・フィーリング仕様

### 3.1 キー中央磁気スナップ（Magnetic Snap ＆ Detent）
ペン先や指でキーを突いた際、接触位置がキーの端に寄っていても、操作感を劇的に向上させるための2段階スナップ補正機構を備えます。

1. **ポインタ微小ワープ (XWarpPointer):**
   - セル接触（`button-press-event`）時、対象セルの幾何絶対中心座標 $(C_x, C_y)$ を計算。
   - GDK / X11 API によりマウスポインタを瞬時に $(C_x, C_y)$ へワープ。
   - これにより、指やペン先に「カチッ」とキー中央に吸い寄せられる（引っかかる）物理的感触を演出。
2. **フリック判定アンカー固定:**
   - フリック計算の起点 $(X_{start}, Y_{start})$ を接触点ではなく $(C_x, C_y)$ に固定。
   - キーの隅をタップしても、プレビューガイドがキーの中心から真円状に対称に展開。
3. **18px ディテント（中心引っかかり抵抗領域）:**
   - 接触位置から半径 18px 以内の移動はすべて `center`（タップ・連打）として扱い、手の微小なブレによるフリック誤判定を完全に防止。

### 3.2 X11 ポインタ拘束（Pointer Confinement）
FlickTux が画面上に表示されている間、ペン先やマウスが誤ってキーボードの外に出て対象アプリをクリックし、フォーカスを失う事故を防ぎます。

- **拘束開始:**
  - ウィンドウの `map` 完了時、Xlib API `XGrabPointer` を発行。
  - `confine_to` パラメータに FlickTux の X11 Window ID を指定。
  - これにより、ポインタは FlickTux の外枠境界線でピタッと留まり、枠外への脱出を阻止。
- **安全解放条件:**
  - `flktux toggle`（F12 等）による非表示化。
  - `Esc` キー押下時。
  - 右上「✕」閉じるボタン押下時。
  - 感度設定画面（`flktux-settings`）の起動時。
  - ヘッダーバーの拘束トグルボタンをクリックした時。

### 3.3 外周縁フレーム（Edge Frame）の 1本指 / 2本指ドラッグ移動
フローティングキーボードの移動を極めて自然に行うため、ウィンドウ外周に 12px 幅の移動マージン（`edge-frame`）を実装。

- **1本指タップドラッグ:**
  - 外周フレームをペン先や指で掴んでドラッグすると、`begin_move_drag` が発火しウィンドウが追従。
- **2本指ドラッグ（トラックパッド）:**
  - 外周フレーム上での `scroll-event`（2本指スクロール）を検知。
  - スムーズスクロール差分 $(\Delta x, \Delta y)$ を直接ウィンドウ位置に反映し、`self.move(x + dx * speed, y + dy * speed)` で指の動きに合わせてスイスイ移動。

## 4. Wacom タブレット感度 ＆ お絵描き最適化仕様

### 4.1 プロファイル詳細

| プロファイル名 | 筆圧カーブ (`PressCurve`) | 閾値 (`Threshold`) | 手ブレ補正 (`RawSample`) | 16:9 比率補正 (`Area`) | 指タッチ |
|---|---|---|---|---|---|
| **イラスト・お絵描き** | `0 20 80 100` (S字軟質) | `10` (極小力で描画) | `4` (なめらか補正) | `0 0 14720 8280` (真円維持) | **OFF** (手のひら誤爆防止) |
| **超機敏・快速** | `0 0 100 100` (直線) | `8` (羽毛タッチ) | `1` (遅延ゼロ) | フルエリア | **ON** (高速トラックパッド) |
| **標準・バランス** | `0 0 100 100` (リニア) | `27` (標準) | `2` (標準) | フルエリア | **ON** |

### 4.2 16:9 正円比率維持の幾何計算
Wacom Bamboo CTH-470 等のネイティブエリアは $14720 \times 9200$（アスペクト比 16:10）。
一般的な 1080p ディスプレイ（16:9）にそのまま投影すると、キャンバス上で正円を描いた際に縦長の楕円に歪みます。
FlickTux は $Y$ 軸の最大値を以下のように自動クリッピングします：
$$\text{Area\_Y} = 14720 \times \frac{9}{16} = 8280$$
コマンド: `xsetwacom set "Wacom ... stylus" Area 0 0 14720 8280`

## 5. 低遅延常駐パイプライン (`XdoPipe`) ＆ Rust コア不可分トグル制御仕様

### 5.1 プロセス常駐化によるレイテンシ削減
従来の方式（1文字ごとに `subprocess.run(["xdotool", ...])`）では、1打鍵ごとにプロセスフォークとダイナミックリンクの遅延（約 20〜40ms）が発生していました。
FlickTux では、バックグラウンドで `xdotool -` を双方向パイプとして常駐させ、標準入力経由でコマンドを連続送信します。
**打鍵レイテンシ: 40ms ➔ 1ms 未満（約40倍高速化）**

### 5.2 小文字・濁点置換のアトミック性保証
Linux の日本語入力（Mozc / Fcitx / IBus）環境下において、`BackSpace` と新文字の送信間隔が短すぎると、イベントキューが逆転して文字が消える問題がありました。
FlickTux の `replace(char)` は以下を単一パイプラインとして不可分に実行します：
```bash
key BackSpace
sleep 0.05
type --delay 10 {char}
```
これにより、濁点・半濁点・小文字（`゛゜小`）を押した際の文字消失バグを 100% 根絶しています。

### 5.3 Rust ネイティブコア (`flktux-rs`) と UI の不可分トグル制御
FlickTux はコアバイナリとして Rust でビルドされた `bin/flktux-rs`、およびフロントエンド UI（`flktux.ui`）で構成されます。
ランチャー `/usr/local/bin/flktux` が `toggle` 引数を受け取ると、以下のプロセス判定を不可分（atomic）に実行します：
- **終了時（すでに起動している場合）**:
  `pgrep -f "flktux\.ui|flktux-rs"` で検出された全プロセスに対し一括で `SIGTERM` を発行し、子プロセスの孤児化を残さず瞬時に完全終了します。
- **起動時（停止している場合）**:
  `flktux-rs` および `flktux.ui` を起動し、最前面にキーボードを表示します。
これにより、F12キーや2本指スワイプの打鍵ごとに「起動 ⇔ 終了」が確実に切り替わります。

```text
├── bin/
│   ├── flktux                     # CLI 実行ファイル (トグル・起動)
```

- **起動導線仕様:**
  - **`F12` グローバルトグルキー**: Cinnamon のカスタムキーバインドにより、あらゆるアプリ前面で `flktux toggle` を実行。ペンタブや液タブのエクスプレスキー・サイドスイッチへの割り当てにも最適。
  - **2本指スワイプジェスチャー (Touchégg)**: Wacom タッチ盤面での2本指上/下スワイプにより、指操作中でも瞬時に起動、起動時にもう一度2本指スワイプで即座に終了（トグル）。
  - **Dock（Plank / パネルランチャー）**: ワンクリックで `flktux toggle` を実行。
  - **アプリケーション一覧**: スタートメニューの「アクセサリ」または検索から起動。
  - **クリーンデスクトップ設計**: デスクトップ画面上にはショートカットアイコンを一切配置せず、画面の美観を維持。

- **ユーザー設定ファイル:**
  - `~/.config/flktux/config.json`: ウィンドウ位置 $(x, y)$、アクティブレイアウト、入力モード、トグル確定時間。
  - `~/.config/flktux/wacom_settings.json`: 筆圧カーブ、閾値、手ブレ補正、16:9比率、タッチON/OFF。
  - `~/.config/touchegg/touchegg.conf`: 2本指スワイプジェスチャー定義。

## 7. 仮入力・文字列表示バー ＆ キーホバー予備入力仕様

### 7.1 ポインタ拘束の完全撤廃 (自由移動)
- 従来搭載されていた `_clamp_pointer`（30ms強制タイマーによる画面ワープ）およびセルタップ時の中心強制移動（`device.warp`）を完全撤廃。
- ペン先やマウスカーソルが画面全体・他ウィンドウへシームレスに脱出・自由移動可能。

### 7.2 仮入力・文字列表示スペース (Display Bar)
- ヘッダー直下にスリムなプレビューバーを配置。
- **2層テキストバッファ同期**:
  - `committed_text`: 確定済み文字列（白文字ボールド表示）。
  - `preedit_text` / `hover_tentative_char`: 仮入力中の文字（水色 `#8ab4f8` ＋ 単一下線表示）。
- **クイックアクション**:
  - `⌫` (BackSpace): 直前の1文字消去。
  - `↵` (Return): エディタへEnter送信し表示スペースを確定クリア。
  - `✕` (Clear): 表示スペースの全クリア。

### 7.3 キーホバー時の予備的仮入力 ＆ 初期点復帰判定
1. **ホバー予備仮入力 (`enter-notify-event`)**:
   - キーの上にポインタが乗った瞬間に、代表文字（center文字: 「あ」「1」「a」等）を取得。
   - エディタ側へ `XDO.type(center_char)`（または直前文字があれば `XDO.replace(center_char)`）を発行し、エディタおよびFlickTux表示スペースに予備配置。
2. **初期点復帰デッドゾーン ($d \le 18\text{px}$)**:
   - フリックドラッグ中、初期点から18px以上離れて方向が検出された後でも、指／ペンを初期点付近（18px以内）に戻せば、即座に中央文字（「あ」）へ自動置換（`replace`）。
   - そのまま離せば中央文字として安全に文字確定（タップ扱い）。
3. **離脱キャンセル (`leave-notify-event`)**:
   - クリック（タップ）されずにキーボード領域外へ離脱した場合、70msタイマーでキャンセルを確定し、エディタに `BackSpace` を送信して仮文字を自動消去。

## 8. 筆圧対応 手書き入力 ＆ 手書き文字配置パッド (Linuxツール再利用)

### 8.1 手書きキーボード入力 (Linux `zinnia` / `tegaki-zinnia-japanese` 連携)
- **Linux標準ツールの再利用**:
  - 描画ストロークの $(x, y, \text{pressure})$ シーケンスを Linux標準の `zinnia-recognize`（`/usr/bin/zinnia-recognize`）に渡し、SVM学習モデル（`tegaki-zinnia-japanese`）で解析。
  - 漢字・ひらがな・カタカナ・英数字・記号の上位候補文字（最大7件）をパッド上部の候補バーにボタン提示。
  - 候補ボタンをタップすると `XDO.type(cand)` によりアクティブウィンドウへ文字コード入力。
  - `zinnia` 未導入環境向けに、軽量幾何ストローク（数字・基本字形）フォールバックも内包。

### 8.2 手書き文字の配置 (Linux `xclip` ＋ `Ctrl+V` 連携)
- **手書き透過画像スタンプ配置**:
  - 描画されたストロークの最小外接矩形（バウンディングボックス）を自動計算し、余白を自動クロップ。
  - 背景透過の白色高精細PNG画像（`/tmp/flktux_handwriting.png`）を生成。
  - Linux標準の `xclip` コマンド（`xclip -selection clipboard -t image/png`）でX11クリップボードへ直接流し込み。
  - 不可分に `XDO.key("ctrl+v")` を発行し、Krita・GIMP・LibreOffice・エディタ等のキャンバス・画面上に手書き文字そのものをワンクリックでスタンプ配置。

## 9. 特化型入力予測補完仕様

### 9.1 通常モード (日常・SNS・メモ)
- 日常会話・SNS・チャットで頻出する挨拶や返答フレーズを即座に予測提示。
- **代表スニペット**:
  - 挨拶・返答: 「お疲れ様です」「ありがとうございます」「よろしくお願いします」「こんにちは」「了解しました」「承知いたしました」「確認します」「助かりました」「問題ありません」「大丈夫です」
  - 記号・感嘆: 「！？」「…」「〜」「（笑）」「（汗）」

### 9.2 ビジネス文書モード (メール・報告書・定型文)
- ビジネスメール、日報、公式文書で必須となる定型敬語表現をワンタップで展開。
- **代表スニペット**:
  - 書き出し: 「いつもお世話になっております。」「平素は格別のご高配を賜り厚く御礼申し上げます。」「お疲れ様です。」「ご無沙汰しております。」「拝啓」
  - 依頼・確認: 「ご確認いただけますと幸いです。」「ご査収のほどよろしくお願い申し上げます。」「ご教示いただけますでしょうか。」「ご検討のほどよろしくお願いいたします。」「何卒よろしくお願い申し上げます。」
  - 連絡・お詫び: 「取り急ぎご連絡申し上げます。」「取り急ぎご報告まで。」「ご不便をおかけして申し訳ございません。」「ご迷惑をおかけし深くお詫び申し上げます。」
  - 結び・ビジネス記号: 「引き続きよろしくお願い申し上げます。」「敬具」「以上、よろしくお願いいたします。」「【重要】」「【共有】」「日時：」「場所：」「担当：」「※」「◆」

### 9.3 小説・創作モード (会話カギ括弧・約物・作法)
- 小説・シナリオ執筆において、日本語の表記作法に準拠した約物や会話文を快適に入力。
- **カッコ自動内側復帰 (`cursor_back_steps`)**:
  - `「」` や `『』`、`（）`、ルビ用 `《》` を挿入した際、自動的に `xdotool` で `Left` キーを送信し、カーソルをカッコの内側へ復帰。手を止めることなく台詞を入力可能。
- **小説作法・約物記号**:
  - 三点リーダー `……` (2文字連結)、ダッシュ `――` (2文字連結)
  - 感嘆符・疑問符＋全角空白: `！　`、`？　`、`！？　`
  - ルビ起点記号 `｜`、字下げ用全角空白 `　`
  - 台詞展開: `「――」`、`「……」`、`（……）`、`――その時、`、`……ふと、`

### 9.4 Linux / UNIX システムコマンド補完
- ターミナル（Terminal, bash, tmux 等）操作時、打鍵数を極小化するコマンド辞書。
- **単一文字からの即時展開**:
  - `s` ➔ `sudo`, `systemctl status`, `systemctl restart`, `ssh`, `sed`
  - `g` ➔ `git status`, `git commit -m ""`, `git diff`, `git pull`, `grep -rnI "" .`
  - `d` ➔ `docker ps`, `docker compose up -d`, `df -h`, `dpkg -i`
  - `a` ➔ `sudo apt update && sudo apt upgrade -y`, `sudo apt install`, `awk`
- **パイプ・リダイレクトのワンタップスニペット**:
  - `| grep `, `| less`, `| head -n 20`, `| awk '{print $1}'`, `> /dev/null 2>&1`, `&& `

### 9.5 多言語プログラミングコード予測
- Python, Rust, Bash, JavaScript/TypeScript, C/C++ の構文・予約語・演算子スニペット（VS Code形式互換）を搭載。
- カッコペア自動挿入時のカーソル内側自動復帰に対応。

### 9.6 アクティブウィンドウ自動検知とモード切替
- `xdotool getactivewindow getwindowname` を定期監視。
- 端末アプリ ➔ 「Linuxコマンドモード」
- テキストエディタ・執筆 ➔ 「小説・創作モード」または「通常モード」
- メール・オフィス ➔ 「ビジネス文書モード」
- ソースコード拡張子 ➔ 各プログラミング言語モード
- ヘッダーのドロップダウンセレクターからもいつでも手動切替可能。
