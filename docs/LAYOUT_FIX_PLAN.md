# FlickTux キー配列修正 & UI一本化・動的グリッド拡張・音声AI受話器連動 実装計画書

## 1. 概要と背景

本計画書は、FlickTux のキー配列忠実再現、UIの抜本的整理・一本化、可変グリッド対応、およびプッシュ電話ハードウェア連動を実現するための完全な技術仕様と実装計画を定義します。

### 1.1 主な要件
1. **スマートフォン3大フリック配列の忠実再現**:
   - **Google (Gboard 12キー 日本語)**: カーソル左右キーを左列に集約、右列にBS・空白・変換・確定を実機通りに配置
   - **iPhone (iOS 日本語かなフリック)**: 左列に `☆123`, `ABC`, `小 ゛゜`, `🌐`、右列に `⌫`, `空白`, `改行 (縦2段 rowSpan:2)`、サブフリックに実機特有の鉤括弧 `「` `」` を設定
   - **Galaxy (Samsung 日本語テンキー)**: 左列に機能キー、右列にBS・カーソル・確定を実機準拠で配置
2. **10キー配列の「あ」重複バグ修正**:
   - 確定ボタンの左隣（Row 4 Col 2）に表示されていた重複「あ」を **`.` (ピリオド/ドット)** に変更
3. **プッシュボタン配列の新設（基本12キー: 4行 x 3列）**:
   - ガラケー配列（4x5連打文字入力）とは完全に独立した、**電話機本来の物理12キー（1-2-3 / 4-5-6 / 7-8-9 / * 0 #）** をベースとするプッシュ電話配列プリセット (`push_phone` / 12キー) を新設
4. **UIの大幅改修：ヘッダーバーの選択ボタン一本化（統合ドロップダウンUI）**:
   - 横並びだった `[Google] [Galaxy] [iPhone] [ガラケー] [10キー]` などのボタン群を全廃
   - **1つの選択UI（`⌨ [レイアウト選択 ▼]`）に集約**し、画面幅の狭小化（3列電話配列など）時にも破綻しないミニマルなUIを実現
   - 公式プリセットだけでなく、**「ユーザーオリジナル（カスタムキーマップ）」** を自動検出し、1つのメニューからシームレスに選択可能にする
5. **キーマップ修正アプリ（Webエディタ）でのボタン増設（動的グリッド拡張）**:
   - 12キー、19キー、20キーなどの固定グリッドにとどまらず、**「行の追加」「列の追加」「セルの追加/削除」** によりユーザーが自由にボタン数を拡張・カスタマイズできるUIとデータ連携を実装
6. **プッシュ電話改造キーボード仕様：受話器フック連動（音声AIチャット起動）とUIフィードバック**:
   - 受話器を持ち上げた（Off-hook）瞬間にユーザー指定の音声AIチャットを起動・接続し、ヘッダーバーに `[📞 通話中]` のステータスインジケーターを表示
   - 受話器を戻した（On-hook）時に通話終了・待機状態へ復帰

## 3. UI改善詳細計画：ヘッダーバーの一本化と動的スケーリング

### 3.1 課題分析とUIリファクタリング方針
- **旧UIの課題**:
  1. ヘッダーバーに `[Google]` `[Galaxy]` `[iPhone]` `[ガラケー]` `[10キー]` と5つものボタンが横並びで配置されていた。
  2. プッシュ電話（3列）などの幅が狭いキーボードでは、ヘッダーのボタンが画面外にはみ出すか極端に圧縮され視認性が崩壊していた。
  3. ユーザーが作成した「ユーザーオリジナル（カスタムキーマップ）」を配置するスペースが存在しなかった。
  4. ドラッグ移動するためのヘッダー余白が失われ、ウィンドウ操作性が低下していた。
- **解決方針**:
  - 横並びボタン群を全廃し、**単一の統合セレクター（`[ ⌨ レイアウト名 ▼ ]`）** に集約。
  - セレクターはドロップダウン（`Gtk.ComboBoxText` またはカスタムメニュー）として動作し、**「標準プリセット」** と **「ユーザーオリジナル」** を整理して一覧表示。
  - ウィンドウ幅をキーボード列数（3列〜5列）に応じて動的に伸縮させ、コンパクトなキーボードでも美しく収まるレイアウトを実現。

### 3.4 レイアウト切替に伴う動的ウィンドウサイズ自動調整仕様

キーボードの列数と行数に応じて、ウィンドウおよびセルのアスペクト比を自動でリサイズします：

| レイアウト種別 | 列数 | 行数 | 推奨ウィンドウ幅 | 推奨ウィンドウ高 | アスペクト比 / 特徴 |
|:---|:---:|:---:|:---:|:---:|:---|
| **プッシュボタン (12キー)** | 3 | 4 | **240 px** | **320 px** | 縦長 (電話機ダイヤルパッド比率) |
| **10キー (電卓式)** | 4 | 5 | **300 px** | **375 px** | 電卓テンキー比率 |
| **Google / Galaxy (20キー)** | 5 | 4 | **360 px** | **290 px** | 横長 (スマートフォン縦画面比率) |
| **iPhone (19キー)** | 5 | 4 | **360 px** | **290 px** | 右下改行キーが2段結合 (rowSpan: 2) |
| **ユーザーオリジナル** | $C$ | $R$ | $C \times 70\text{px} + 10$ | $R \times 68\text{px} + 40$ | 動的グリッド自動計算 |

- **リサイズ処理フロー**:
  1. ドロップダウンからレイアウトが選択される
  2. マトリックス定義から最大列数 $C$ および行数 $R$ を算出
  3. `window.resize(target_width, target_height)` を実行
  4. グリッド内の旧セルを全破棄し、新しいキーセルを再生成・配置
  5. アプリケーション設定ファイル (`~/.config/flktux/config.json`) に現在のレイアウト名を永続化

### 3.5 プッシュ電話改造キーボード：受話器フック連動UIステータスインジケーター

電話機を改造したハードウェアにおいて、受話器を持ち上げている間、ユーザーに現在の通話/AI接続状態を明示するフィードバックUIを提供します：

```text
[受話器 Off-hook (持上)]  --->  ヘッダーバー右側に [📞] バッジが点滅・点灯
                                ウィンドウ外枠にシアン/グリーンのアクティブグロー
                                ユーザー指定の音声AI (Gemini/ChatGPT等) 起動
[受話器 On-hook (戻す)]   --->  [📞] バッジ消灯、外枠は通常ダークグレーへ復帰
                                音声AIセッション切断
```

- **インジケーター仕様**:
  - 通常時: 非表示またはグレーアウト
  - 通話接続中: エメラルドグリーン (`#34a853`) またはシアン (`#8ab4f8`) でアクティブ表示
  - ツールチップ: `音声AI通話中 (受話器 Off-hook)`

## 4. キーマップ修正WebエディタUI：動的グリッド拡張（ボタン増設）とオリジナル管理

ユーザーが「自分専用のオリジナルキー配列」を作成・編集するための Web エディタ (`web/index.html`) の UI 仕様：

### 4.1 グリッド拡張コントロール（行・列の動的増設/削除）
- **コントロールパネル**:
  - `[➕ 行を追加 (下)]`: 最下部に空キー行を追加（例: 4行 → 5行）
  - `[➖ 行を削除]`: 最下部の行を削除
  - `[➕ 列を追加 (右)]`: 最右列に空キー列を追加（例: 3列 → 4列 → 5列）
  - `[➖ 列を削除]`: 最右列を削除
- **グリッド寸法表示**:
  - 現在の寸法をリアルタイム表示（例: `📐 4 行 × 5 列 (合計 20 キー)`）

### 4.2 キーセル編集モーダル
- セルをクリックすると右サイドパネルに詳細エディタを表示：
  - **セルタイプ**: フリックキー (`flick`) / 機能アクション (`action`)
  - **フリックマトリックス (十字)**:
    - 中央 (タップ文字)
    - 上フリック文字
    - 下フリック文字
    - 左フリック文字
    - 右フリック文字
  - **セル結合**:
    - `rowSpan` (縦結合: iPhone改行キーなど)
    - `colSpan` (横結合: スペースバーなど)

### 4.3 ユーザーオリジナル保存と本体UIへの即時反映パイプライン
1. 編集完了後、`[💾 ユーザーオリジナルとして保存]` をクリック
2. 配列名（例: `my_custom_16key`）を入力
3. Webエディタのバックエンド API (`/api/presets/custom`) が `~/.config/flktux/custom/my_custom_16key.json` に書き込み
4. FlickTux 本体のレイアウトセレクターに `★ my_custom_16key (カスタム)` が即座に追加・選択可能となる

## 5. プッシュ電話改造キーボード仕様：受話器フック連動（音声AIチャット接続）

### 5.1 動作シーケンス
1. **Off-hook（受話器を上げる）**:
   - 電話機のフック（マイクロスイッチ / リードスイッチ）が作動
   - evdev（キーイベント `KEY_PHONE` / マウスボタン / GPIO / シリアル等）として FlickTux が検出
   - UIヘッダーの `[📞]` インジケーターが点灯
   - 設定された **音声AIチャット起動コマンド** を即座に非同期実行
   - （例: ブラウザで ChatGPT Voice / Gemini Live 画面を開く、またはローカル音声対話デーモンと接続）
2. **On-hook（受話器を戻す）**:
   - フックスイッチが戻る
   - UIヘッダーの `[📞]` インジケーターが消灯
   - 通話終了コマンド（または音声AIウィンドウの終了・ミュート処理）を実行

### 5.2 設定スキーマ (`configs/config.json`)
```json
{
  "hook_trigger": {
    "enabled": true,
    "input_device": "/dev/input/by-id/usb-telephone-hook-event",
    "event_type": "EV_KEY",
    "event_code": "KEY_PHONE",
    "on_offhook": "xdg-open 'https://gemini.google.com' || /usr/local/bin/start_voice_ai.sh",
    "on_onhook": "pkill -f voice_ai || /usr/local/bin/stop_voice_ai.sh"
  }
}
```
